# Capability map

What each Shipyard mechanism becomes under Copilot, with an honest fidelity word: **full** = the same guarantee;
**degraded** = works but weaker or client-dependent; **manual** = convention plus a later check, not enforcement
at the moment of action. Anything marked (unverified) came from a single source or a page that was silent on the
point; confirm it against `copilot --help` and your client before relying on it.

| Shipyard mechanism | Copilot equivalent | Fidelity | How the gap is handled |
|---|---|---|---|
| **Coordinator** as the main session, sole entry point, owns the chat and gates | `.github/agents/shipyard-coordinator.agent.md`, launched with `copilot --agent=shipyard-coordinator` (CLI), picked in the IDE, or named in a cloud task | degraded | Specialists set `user-invocable: false` and `disable-model-invocation: true`, so only an agent that names them in `agents:` can call them; the coordinator's `agents:` lists exactly the twelve and every specialist has `agents: []` and no `agent` tool. `Caller:` stays a convention; the `brief-check` hook (CLI) checks it on `task` calls. |
| **Saved workflows** `discover.js`, `plan.js`, `slice.js` (order, caps, routing, dedupe, schema-checked returns) | Dynamic workflows `.github/extensions/shipyard-{discover,plan,slice}/extension.mjs` | degraded (CLI-only, public preview) | Same three-workflow split, each ending at a gate. IDE and cloud fall back to the phase prompt files, whose first step is `check.py --phase` and whose returns are validated with `shipyard_validate.py`. Caps and routing become instructions, verified after the fact by `check.py`. |
| **Role registry** `registry/roles.json` | Same file under `shipyard/registry/roles.json`; agent names `shipyard-<short>`; `.agent.md` `model` written from it by `gen_agents.py` | degraded | Effort per mode is not expressible in `.agent.md`; the generator emits `model` only (and only once you set the ids). `ctx.agent` names the custom agent, the model (Copilot ids via the lib's `MODEL_IDS` / `args.models`) and the effort per call; verified on CLI 1.0.108. |
| **Agent shells** (identity, tools, model, effort, maxTurns, skills preload) | `.github/agents/*.agent.md` with `name`, `description`, `tools`, `model`, `user-invocable`, `agents`, `handoffs` (VS Code), `hooks` (CLI); body = the Shipyard shell with tool names mapped | full for identity and tools; degraded for effort, turn caps and preload | Skills load by relevance, so each body says "Load these skills from `.github/skills` before you start". `maxTurns` becomes the `Budget:` line in every brief plus workflow `limits`. |
| **Capability skills** | `.github/skills/<name>/SKILL.md`, same content with paths and names adapted | full | Code review on GitHub.com also loads them, a free reviewer surface on every pull request. |
| **Contracts** `contracts/*.schema.json` | Same files under `shipyard/contracts/`; `ctx.agent(…, {schema})` enforces a structural subset inside workflows; everywhere else the caller runs `shipyard_validate.py` | degraded | A `null` return is retried once, then `BLOCKED`. |
| **Hook: protect-branches** | `.github/hooks/shipyard.json` `preToolUse` on the shell tool, plus agent-scoped in every agent file (CLI), plus the `main` ruleset | degraded locally, full remotely | The hook cannot see which agent runs; it reads `SHIPYARD_ROLE` or `state.json` → `activeRole`. The ruleset is the real guarantee: no bypass for Copilot. |
| **Hook: write-scope** | CLI: agent-scoped `hooks` carrying `SHIPYARD_ROLE=<short>`; cloud: the repository hook infers the role from `activeRole`, set by the coordinator before each delegation; IDE: `tools` restriction only | degraded | `shipyard-slice-check` compares the pull-request diff with the touch sets. |
| **Hook: test-plan-gate** | Same hook file, same inference; `shipyard-slice-check` also refuses a slice whose `TEST_PLAN.md` was approved after the first code commit | degraded | Order violations are caught at pull-request time if the hook missed them. |
| **Hook: readonly-bash** | `tools: [read, search, …]` in the reviewer and planner agent files, with `execute` kept only where tests must run, guarded by the hook | full (stronger where the tool is absent) | — |
| **Hook: goldfish-blinders** | Agent-scoped `preToolUse` on the read tools denying `.ai/**` except `SLICE.md` (CLI) | degraded | IDE and cloud: the brief carries only the verbatim request; unenforced. |
| **Hook: secrets-guard** | `preToolUse` on the edit tools into `.ai/**`, plus push protection on the notes branch | full remotely, degraded locally | — |
| **Hook: findings-gate** | `subagentStop` → `{decision: "block"}` when the findings file is missing, stale or malformed (CLI, cloud) | degraded | Whether the `matcher` sees the custom agent name is (unverified); inside workflows the `schema` on `ctx.agent` is the primary gate. |
| **Hook: brief-check** | `preToolUse` on the `task` tool (CLI) | degraded | Workflows build briefs in code; direct calls in IDE and cloud are convention. |
| **`.ai/` folder** excluded via `.git/info/exclude` | Same folder and scripts; the cloud agent clones fresh, so `copilot-setup-steps.yml` restores `.ai/` from the notes branch and adds the exclude line | degraded in cloud | The notes branch is updated from Actions in cloud mode (`shipyard-notes-sync.yml`). |
| **Notes branch** `<feature>-shipyard` | Same via `shipyard_state.py snapshot` (CLI, IDE); cloud: an Action commits the uploaded artifact | manual in cloud | A lost artifact means a lost phase; every cloud task also posts a summary comment. |
| **Human gates** P0, P4, P8, merge | CLI: chat; IDE: handoffs with `send: false`; cloud: issue form, comments, the `shipyard:plan-approved` label, pull-request review | full (CLI, IDE), manual (cloud) | `shipyard_state.py gate <P> approve --by <login>` records approvals; `check.py --phase` refuses to proceed without them. |
| **Local `--no-ff` merge** into the feature branch | CLI and IDE: identical; cloud: a pull request from the slice branch into the feature branch, merged by a human with a merge commit (ruleset) | full / manual | The evidence summary goes into the pull-request body instead of the merge commit message. |
| **Compute classes** COORDINATOR/DEEP/STANDARD | `model` per agent file from the registry (ids set by you); effort global (CLI `effortLevel`) or SDK-only `reasoningEffort` (unverified for the CLI) | degraded | VS Code's cost-tier ceiling gives "delegate never above coordinator" for free. |
| **Parallelism** (implementer ∥ verifier, concurrent reviewers) | `ctx.parallel` in workflows; parallel subagents where the client supports them | degraded outside workflows | Prompt files allow sequential runs; acceptable. |
| **Evals** (the original plugin's eval suites) | None | manual | Conformance runs of the sample project with `copilot workflow run … --result-file` (planned). |
| **Plugin install / marketplace** | `copilot plugin install vineethvarghese/shipyard-copilot` (CLI: agents, skills, hooks, workflows; verified on 1.0.107) and `install.sh` / `install.py init|update|status|remove` for a checksummed project install that every client reads | supported | No marketplace listing yet; `copilot plugin uninstall shipyard` and `install.py remove` are the two uninstalls. |
